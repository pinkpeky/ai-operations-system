# 运营项目服务器端与客户机前端设计

日期：2026-05-30

## 设计结论

客户机前端是工作人员的主工作台。工作人员应通过客户机发起运营任务、导入素材、完成审批、预览产出、挑选最终作品、确认发布包，并在客户机执行真实发布和回填结果。

服务器前端是管理员和维护人员的控制台。它负责模型、ComfyUI、队列、运行资源、异常恢复、审计、数据同步和后台配置，不应成为普通工作人员每天操作的复杂后台。

这个分工比“所有能力都堆在服务器后台”更合理，因为真实社媒环境、OpenClaw、Playwright、账号登录态和人工确认都发生在客户机，工作人员也更需要一个简洁的任务工作台，而不是底层工程面板。

## 客户机前端职责

客户机前端包括 Web Console 和 Desktop Console，后续应以 Desktop Console 为正式工作人员入口，Web Console 可作为轻量备选。

必须包含以下能力：

### 1. 运营任务创建

工作人员只需要填写业务语言，而不是工程参数：

- 运营主题。
- 运营目标。
- 平台，例如抖音、小红书、视频号。
- 目标客户和风格偏好。
- 内容类型，例如图文、短视频、音频、图文加视频组合。
- 发布频率和周期。
- 禁止事项和品牌限制。

提交后由客户机把任务发送到服务器，服务器生成运营方案。

### 2. 素材导入

客户机前端必须有清晰的素材导入入口，所有素材都归属到具体运营项目。

素材类型至少包括：

- 参考视频。
- 场景图。
- 产品图。
- 人物或数字人授权素材。
- 音频、歌曲、配音、环境音。
- 品牌资料。
- 脚本文档。
- 历史发布链接或数据截图。

素材导入后应显示：

- 上传状态。
- 解析状态。
- 是否可用于 ComfyUI。
- 授权状态。
- 所属项目。
- 关联的生产任务。

### 3. 所有业务审批

客户机前端必须承接所有工作人员审批，不应要求工作人员进入服务器后台审批。

审批类型包括：

- 运营方案审批。
- 文案任务审批。
- 图片任务审批。
- 影音任务审批。
- ComfyUI 工作流选择审批。
- 候选作品终选审批。
- 发布文案审批。
- 发布包审批。
- 客户机执行结果确认。
- 数据观察和优化建议确认。

审批界面必须是业务语言：

- 通过。
- 驳回。
- 要求修改。
- 备注原因。
- 查看关联素材和产出。

不应让工作人员阅读原始 JSON、节点图参数或底层调度记录。

### 4. 流的选择

客户机前端必须包含流的选择。这里的“流”不是让工作人员直接编辑 ComfyUI 节点，而是选择业务可理解的工作流候选。

流的选择应覆盖：

- 图片生成流。
- 图片编辑流。
- 视频生成流。
- 动作迁移流。
- 数字人流。
- 音频生成流。
- 音频处理流。
- 音视频合成流。
- 字幕、封面、超分、补帧等后处理流。

每个候选流应显示：

- 工作流名称。
- 适合项目。
- 输入素材要求。
- 输出类型。
- 推荐原因。
- 预计耗时。
- 显存需求。
- 成功率或风险提示。
- 是否需要人工上传额外素材。
- 是否已在当前服务器验证可运行。

工作人员可以执行：

- 选择此流。
- 要求换一个流。
- 查看示例效果。
- 查看输入缺口。
- 审批通过。
- 驳回并填写原因。

Agent 可以推荐流，但不能直接替工作人员最终确认。最终选择必须形成 `WorkflowSelection` 记录，并绑定到具体 `ProductionTask`。

### 5. 产出预览

客户机前端必须包含候选产出预览。没有预览就不能形成可靠审批。

预览对象包括：

- 图片候选。
- 视频候选。
- 音频候选。
- 音视频合成候选。
- 封面图。
- 字幕文件。
- 发布文案。
- 发布包预览。

每个候选产出应显示：

- 来源生产任务。
- 使用的工作流名称。
- 生成时间。
- 版本号。
- 状态。
- 预览播放器或缩略图。
- 选择为最终作品。
- 返工意见。

### 6. 发布包确认

客户机执行真实发布前，工作人员必须看到完整发布包：

- 平台。
- 账号。
- 最终图片、视频或音频。
- 封面。
- 标题。
- 正文。
- 话题。
- 发布时间。
- 风险提示。
- 审批状态。

只有发布包审批通过后，客户机才能进入 OpenClaw / Playwright 执行。

### 7. 客户机执行和结果回填

客户机前端负责真实平台执行状态：

- 本机 Worker 状态。
- OpenClaw 状态。
- Playwright 状态。
- 登录态提示。
- 发布队列。
- 执行中状态。
- 发布成功或失败。
- 失败原因。
- 发布链接或作品 ID。
- 人工补录入口。

客户机不应绕过审批直接发布。

## 服务器前端职责

服务器前端不应该成为普通工作人员主界面。它应服务于管理员、技术维护和运营负责人。

### 1. 项目总览和异常总览

服务器前端应显示：

- 当前运营项目列表。
- 项目阶段。
- 阻塞原因。
- 待审批数量。
- ComfyUI 队列状态。
- 客户机在线状态。
- 发布和数据回收异常。

### 2. ComfyUI 和模型维护

服务器前端负责：

- ComfyUI 健康状态。
- GPU 和队列资源。
- 工作流模板注册。
- 工作流运行前检查。
- 模型缺失提示。
- 显存和耗时预估。
- 失败恢复。

这部分不应直接暴露给普通工作人员。

### 3. 工作流知识库维护

服务器前端负责维护结构化工作流知识：

- 工作流名称。
- 适用场景。
- 输入要求。
- 输出类型：图片、视频、音频、音视频组合。
- 显存需求。
- 平均耗时。
- 风险和限制。
- 推荐项目类型。

Agent 只能在这个结构化候选集中推荐工作流，最终仍由客户机工作人员确认。

### 4. 审计和后台配置

服务器前端负责：

- 审批链路审计。
- 执行日志。
- 发布结果审计。
- 平台 connector 配置。
- 客户机注册。
- 权限管理。
- 失败任务恢复。

## 页面结构建议

### 客户机前端

建议保留极少主导航：

1. 任务台
2. 素材
3. 审批
4. 流选择
5. 产出
6. 发布
7. 数据

其中“任务台”是默认首页，工作人员进入后只看到：

- 当前项目。
- 下一步要做什么。
- 待审批。
- 待选择的流。
- 最新产出。
- 发布状态。
- 一个主要操作按钮。

### 服务器前端

建议主导航为：

1. 项目监控
2. ComfyUI
3. 工作流库
4. 客户机
5. 数据回收
6. 审计
7. 设置

服务器前端可以信息密度更高，但仍应避免把所有底层对象铺满首页。

## 前端设计原则

1. 工作人员只看业务对象，不看工程对象。
2. 客户机完成审批、预览、导入、终选和发布确认。
3. 服务器管理资源、运行、安全、异常和审计。
4. 每个页面只突出一个下一步动作。
5. 所有生成结果先进入候选池，再由人工终选。
6. 所有真实发布必须经过发布包审批。
7. 音频、视频、数字人都归入影音流，但前端应显示为清晰的任务类型。
8. ComfyUI 工作流选择必须可解释，不应让 Agent 自由猜。
9. 流选择必须发生在客户机前端，服务器前端只维护流库和运行状态。

## 对后端的要求

为了支撑上述前端，后端需要补齐以下对象：

- `OperationPlan`：运营方案。
- `ProjectMaterial`：项目素材。
- `ProductionTask`：生产任务，类型包括 copy、image、media。
- `WorkflowSelection`：工作流选择记录。
- `OutputCandidate`：候选产出。
- `FinalSelection`：最终选择。
- `PublishPackage`：发布包。
- `PlatformMetricSnapshot`：平台数据快照。

这些对象完成后，客户机前端才能做到简洁；否则前端只能继续把底层商业运营、ComfyUI、数字人、执行记录分散展示。
