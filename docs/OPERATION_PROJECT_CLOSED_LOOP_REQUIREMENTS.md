# 运营项目闭环需求定义

更新日期：2026-05-30

## 1. 总目标

系统的主对象不是单个视频、单张图片或一次 ComfyUI 任务，而是一个可持续运营的项目。

用户输入运营主题和目标后，系统应生成可审批的运营方案，再按方案逐步进入文案流、图片流、视频流、发布流和数据分析流。每个关键阶段必须可追踪、可审批、可中断、可复用、可回滚，素材和输出必须按项目规范管理。

## 2. 标准闭环

```text
运营主题 / 目标输入
  -> 运营方案生成
  -> 人工审批运营方案
  -> 文案 / 图片 / 视频生产任务拆分
  -> 人工选择海报和视频 ComfyUI 工作流
  -> ComfyUI 或其他工具输出候选成品
  -> 人工挑选最终作品
  -> 针对作品编写社媒发布文案
  -> 人工审批发布内容
  -> 客户机接管 OpenClaw / Playwright 真实发布
  -> 定时拉取平台数据
  -> 数据回传服务器
  -> 闭环分析和下一轮优化建议
```

## 3. 运营项目管理

每个运营项目需要独立管理，不应散落在视频任务、图片任务或单次发布任务里。

项目应至少包含：

- 项目标题
- 运营目标
- 目标人群
- 目标平台
- 业务约束
- 成功指标
- 当前阶段
- 审批状态
- 素材集合
- 产出集合
- 发布计划
- 数据观察计划
- 优化记录

当前代码里的 `CommercialOperation` 可以作为项目主对象继续扩展。后续不建议新建一套平行项目模型，除非现有模型无法承载资产治理和发布计划。

## 4. 运营方案输出

运营方案是第一份核心产物，必须先审批再进入生产。

运营方案应包含：

- 项目目标拆解
- 内容策略
- 平台策略
- 文案任务列表
- 图片任务列表
- 视频任务列表
- 素材需求
- 预计工作流类型
- 审核标准
- 发布频率和发布窗口
- 数据观察指标
- 风险边界

边界：运营方案阶段不生成最终作品，不调用 ComfyUI，不发布，不控制账号。

## 5. 文案流

文案流负责生成和维护：

- 标题
- 正文文案
- 视频口播脚本
- 海报文案
- 评论区引导
- 私信承接话术
- 社媒发布文案

文案不应一次性混在视频 prompt 中。视频 prompt、海报 prompt、社媒文案是不同层级的内容，需要独立记录、审批和复用。

## 6. 图片流

图片流负责：

- 海报需求生成
- 图片 ComfyUI 工作流候选
- 人工选择工作流
- Prompt 和参数生成
- 候选图输出
- 人工挑选最终图
- 最终图进入项目输出库

图片流不能覆盖原始 workflow。实际执行时应复制 workflow 或生成运行时参数副本，保留原始模板不变。

## 7. 视频流

视频流负责：

- 视频需求生成
- 分镜和动作要求
- 首帧 / 参考图 / 参考视频整理
- 视频 ComfyUI 工作流候选
- 人工选择工作流
- Prompt 和参数生成
- 候选视频输出
- 人工挑选最终视频
- 最终视频进入项目输出库

视频流不是固定口播流。它应支持数字人、图生视频、动作迁移、参考视频复刻、唱跳、镜头感、素材混剪等不同工作流类型。

## 8. 工作流选择

工作流选择由系统给出候选，最终由人工确认。

原因：

- ComfyUI 工作流质量差异大
- 模型依赖和显存需求不同
- 同一任务可能有多个可行路径
- 当前阶段完全自动选择风险较高

因此推荐模式是：

```text
Agent 推荐 3-5 个候选工作流
  -> 展示适用场景、输入要求、输出类型、风险、预计耗时
  -> 人工选择工作流
  -> 系统生成参数和运行副本
  -> 执行并记录输出
```

## 9. 成品挑选

ComfyUI 或其他生成工具输出后，系统不应自动默认某个成品就是最终作品。

需要有候选作品管理：

- 候选作品列表
- 缩略图 / 预览
- 生成参数
- 来源工作流
- 成本和耗时
- 质量检查结果
- 人工选择状态
- 淘汰原因
- 最终入选作品

只有被人工挑选的作品才能进入发布文案编辑和发布审批阶段。

## 10. 社媒发布文案编辑

最终作品确定后，需要针对每个发布平台生成独立发布内容。

例如同一个视频发布到抖音和小红书，应分别记录：

- 平台
- 标题
- 正文
- 话题标签
- 封面
- 首评
- 私信承接话术
- 发布窗口
- 风险提示

这一步也必须审批。审批通过后才进入客户机执行。

## 11. 客户机真实发布

真实发布只能在客户机执行，由客户机接管 OpenClaw / Playwright。

服务器负责：

- 生成发布执行请求
- 下发已审批内容
- 下发执行 runbook
- 接收执行结果
- 保存证据和状态

客户机负责：

- 使用真实浏览器环境
- 使用客户账号登录态
- 执行 OpenClaw / Playwright 发布
- 返回成功、失败、截图、链接和异常信息

边界：服务器不直接控制真实账号，不绕过验证码、代理、指纹、平台风控，也不绕过人工审批。

## 12. 定时数据分析

每个运营项目需要配置数据观察计划。

最小需求：

- 平台
- 发布作品 ID 或链接
- 观察频率，例如每天一次
- 指标列表，例如播放量、点赞、评论、转发、收藏、完播率、私信、线索
- 数据拉取方式
- 失败重试策略
- 数据回传记录

拉回的数据进入服务器后，应生成：

- 数据观察记录
- 表现摘要
- 异常提示
- 优化建议
- 下一轮内容方向

## 13. 素材管理

素材需要按项目规范管理，不能只靠本地文件夹。

素材类型：

- 场景图
- 人物图
- 产品图
- 参考视频
- 音频
- 品牌资料
- 文案资料
- 平台账号资料引用
- 授权证明

素材记录应包含：

- 所属项目
- 素材类型
- 文件路径或 URI
- 来源
- 授权状态
- 可用范围
- 标签
- 版本
- 质量备注

## 14. 输出管理

输出也需要按项目规范管理。

输出类型：

- 运营方案
- 文案
- 海报
- 首图
- 视频
- 封面
- 社媒发布稿
- 发布结果
- 数据分析报告
- 优化方案

输出记录应包含：

- 所属项目
- 所属阶段
- 输出类型
- 文件路径或 URI
- 生成来源
- 使用的工作流
- 使用的 prompt
- 使用的模型
- 参数快照
- 审批状态
- 是否最终入选
- 发布状态
- 数据表现

## 15. 当前代码对应关系

现有底座可以继续使用：

- `CommercialOperation`：运营项目主对象
- `CommercialOperationContentDraft`：文案、脚本、发布文案草稿
- `CommercialOperationAssetRequest`：图片 / 视频 / 设计等生产需求和成品资产挂接
- `CommercialOperationDeliverable`：可审批交付包
- `CommercialOperationExecutionRequest`：客户机执行准备
- `CommercialOperationExecutionRun`：客户机执行过程
- `CommercialOperationResult`：发布结果
- `CommercialOperationMonitoringObservation`：数据观察
- `CommercialOperationOptimizationDecision`：优化决策
- `DigitalHumanVideoJob`：数字人视频生产任务
- `DigitalHumanAsset`：数字人相关素材和视频成品
- `OutputArtifact`：通用输出库

当前缺口：

- 运营方案还没有成为强约束的一级审批产物
- 图片流还没有完整的候选工作流、执行副本、候选作品挑选过程
- 视频流已经有部分数字人链路，但候选作品挑选和社媒文案阶段仍需补齐
- 素材库还需要项目级分类、授权、版本和引用关系
- 输出库还需要项目级最终入选、发布状态和数据表现字段
- 定时平台数据拉取还没有真实接入

## 16. 推荐下一阶段

下一阶段不应继续优先深挖某一个 ComfyUI 视频流。更合理的下一步是 Phase 68B：运营项目生产计划和资产治理。

Phase 68B 建议实现：

- 运营方案作为正式产物生成和审批
- 从运营方案拆分文案、图片、视频生产任务
- 项目级素材清单
- 项目级输出清单
- 候选作品和最终入选状态
- 工作流选择记录只保存引用和参数副本，不覆盖原 workflow

完成 Phase 68B 后，再进入 Phase 68C：社媒发布文案审批和客户机发布计划。
