# KTV AI 虚拟数字人视频 0-1 工作流方案

更新日期：2026-05-27

## 1. 目标重新定义

本项目目标不是“把人物照片抠进场景”，也不是“让 Wan I2V 自己从空房间里凭空长出一个人”。

目标应定义为：

> 输入一张 KTV / 商 K / 包厢 / 会所场景图，系统自动生成一个同场景、同灯光、同空间透视的 AI 虚拟美女数字人，并进一步生成可用于短视频宣传的动态镜头。

允许的输入：

- 场景图：必须支持。
- 场景视频：后续支持。
- 用户指定人物照片：可作为独立模式，但不是当前主线。
- 虚拟人物设定：可选；如果用户不提供，则系统自动生成一个虚拟美女角色。

不采用的主线：

- 不把真实人物画像抠图贴进场景。
- 不把一次 SDXL inpaint 成功当作完整工作流。
- 不依赖单次 prompt 运气。

## 2. 为什么上一版效果不够

上一版跑通了“场景图 -> SDXL 局部生成人物 -> Wan I2V 动起来”，但它只能证明链路能运行，不能证明能达到商业级效果。

主要问题：

- 人物没有身份锁定：每次生成的脸、身材、服装可能变化。
- 只有单张合成关键帧：视频阶段没有足够的人物控制条件。
- Wan I2V 更擅长让已有画面动起来，不擅长在空场景中稳定新增高质量人物。
- 没有姿态、深度、遮挡、灯光一致性约束。
- 没有分镜、脚本、镜头类型和质检门槛。

所以正确路线应是“先生成并锁定虚拟角色，再把角色按场景规则放入场景，再用动作/姿态控制生成视频”。

## 3. 推荐主流程

### 阶段 A：生成虚拟美女角色资产

输入：

- 业务风格：商务 KTV、高级、真实、接待感。
- 可选要求：年龄段、服装、气质、发型、镜头风格。

输出：

- 虚拟角色设定卡。
- 正脸半身图。
- 全身站姿图。
- 侧脸 / 微笑 / 拿麦 / 引导手势参考图。
- 统一 negative prompt。

验收：

- 同一个角色在 4-6 张参考图里脸型、发型、服装一致。
- 不是网红写真风，必须像商务场景主持 / 接待 / 氛围官。

当前可用方案：

- 低配起步：SDXL / SDXL inpaint 生成角色参考。
- 更优主线：补齐 Flux / SDXL + IPAdapter / InstantID / FaceID / LoRA 类身份保持能力。
- 商业稳定线：固定一个虚拟角色后训练小 LoRA，作为本店专属虚拟人。

### 阶段 B：场景解析

输入：

- `D:\流程测试\场景素材` 下的场景图或视频帧。

处理：

- 统一裁切到竖屏 9:16。
- 判断可站立区域、沙发/桌面/墙面遮挡。
- 生成深度/分割/人物插入 mask。
- 记录灯光颜色、主色调、透视方向。

输出：

- 标准场景底图。
- 人物插入区域 mask。
- 场景描述 prompt。
- 灯光和镜头约束。

验收：

- 人物不会站在桌子上、穿过沙发、遮挡关键卖点。
- 人物大小符合空间透视。

### 阶段 C：生成“角色锁定 + 场景融合”关键帧

输入：

- 阶段 A 的虚拟角色参考。
- 阶段 B 的场景底图与 mask。

处理：

- 使用 inpaint / image edit，把同一个虚拟角色生成进场景。
- 用角色参考控制脸、发型、服装。
- 用场景 mask 控制位置。
- 用场景 prompt 控制灯光和空间。

输出：

- 关键帧 1：全身站立介绍。
- 关键帧 2：半身拿麦口播。
- 关键帧 3：引导手势 / 侧身展示场地。

验收：

- 人物与场景光照统一。
- 脸部不崩，手部可接受。
- 同一角色跨关键帧一致。
- 场景仍能看出来自原始场景。

### 阶段 D：动作视频生成

输入：

- 角色场景融合关键帧。
- 姿态/动作参考：站立、轻微转身、拿麦、手势。
- 可选语音。

处理：

- 全身动作镜头：优先使用 WanAnimate。
- 纯场景动效：使用 Wan I2V。
- 半身口播：使用 MuseTalk / AdvancedLivePortrait / 后续更强口型方案。

输出：

- 2-5 秒单镜头视频片段。

验收：

- 人物不漂移、不融化、不频繁换脸。
- 服装和脸部大体稳定。
- 动作幅度小但可信，符合商务宣传风格。

### 阶段 E：成片编排

输入：

- 多个镜头片段。
- 旁白 / 字幕 / BGM。

处理：

- 主持人开场。
- 场景展示。
- 服务/价格/优势镜头。
- 主持人收尾。
- 字幕、转场、音乐、音量标准化。

输出：

- 竖屏成片 MP4。
- 预览图 contact sheet。
- 质检报告。

验收：

- 15-30 秒短视频完整可看。
- 至少 1 个高质量虚拟人镜头。
- 场景素材不是简单拼接，而是被 AI 重新包装。

- 还没有把“虚拟角色参考 + 场景 mask + WanAnimate 动作控制”整理成单一可复用工作流。
- 还没有针对每个镜头的自动质检和失败重试策略。
- ComfyUI 云端 Flux Kontext 节点需要登录，不能作为本地稳定主线。

## 5. 0-1 最小可行版本

第一版不要追求一次生成完整大片，应先把一个闭环跑稳：

1. 从 `D:\流程测试\场景素材` 选 1 张场景图。
2. 生成 1 个固定虚拟美女角色参考。
3. 把该虚拟角色融合进场景，输出 3 张关键帧。
4. 选最好的一张关键帧，用 WanAnimate / Wan I2V 生成 2-4 秒短镜头。
5. 输出 MP4 + contact sheet + 质检备注。

成功标准：

- 不是抠图人物。
- 是 AI 虚拟美女。
- 场景来自用户素材。
- 人物和场景融合自然。
- 视频中人物稳定性明显好于单纯 SDXL + Wan I2V。

## 6. 下一步执行顺序

优先级 1：角色锁定

- 生成一套虚拟美女角色参考图。
- 选定一个角色作为“明子式 KTV 虚拟主持人”。
- 后续所有镜头必须引用同一个角色参考。

优先级 2：关键帧质量

- 从 `D:\流程测试\场景素材\4.jpg` 继续做。
- 生成 3 个候选场景融合关键帧。
- 人工选 1 个最自然的作为视频源。

优先级 3：视频控制

- 先做小动作：轻微呼吸、微笑、拿麦、手势。
- 不先做大幅走路和跳舞，因为大幅动作更容易崩。
- 比较 Wan I2V 与 WanAnimate 两条输出，保留更稳的路线。

优先级 4：自动化脚本

- 增加一个统一入口：

```powershell
D:\ai-operations-system\.venv\Scripts\python.exe D:\ai-operations-system\scripts\commercial_ktv_workflow.py virtual-host-pipeline `
  --scene-image "D:\流程测试\场景素材\4.jpg" `
  --label ktv_virtual_host_v1
```

该命令最终应产出：

- `character_refs/`
- `scene_keyframes/`
- `video_clips/`
- `final/`
- `quality_report.md`

## 7. 结论

当前方向应从“单次生成测试”升级为“角色资产 + 场景融合 + 动作控制 + 成片质检”的生产链路。

上一版 SDXL 虚拟美女图可以作为验证样张，但不能作为最终方案。真正要接近抖音示例效果，必须先锁定虚拟角色，再用场景和动作控制生成视频。
