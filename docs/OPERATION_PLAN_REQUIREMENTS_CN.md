# 运营方案生成与验证需求

更新时间：2026-06-03

## 1. 目标

运营方案是运营项目进入生产前的第一个正式业务产物。它不能只是 LLM 口头总结，也不能只是前端静态卡片展示。系统必须围绕当前项目，结合项目知识库、项目素材、公开网络情报、同题材热门视频线索、竞品打法、平台公开规则和运营目标，生成一份可审核、可修改、可批准、可派生生产任务的完整方案。

方案验证必须通过浏览器真实操作完成。所有关键动作都要在浏览器页面中真实点击、输入、提交、刷新和核验结果，不能只用接口返回、静态截图或代码阅读来替代产品验收。

## 2. 项目绑定

所有方案、知识库、素材、文案、影音任务、发布包和数据回流都必须绑定到当前项目。

项目切换时：

- 方案页只展示当前项目的方案版本。
- 知识库只展示当前项目的资料。
- 素材库只展示当前项目的素材。
- 生产任务只来自当前项目已批准的最新方案。
- 数据回流只展示当前项目发布后的真实或人工回填指标。

## 3. 知识库前置规则

方案生成前必须检查当前项目知识库。

如果知识库缺少内容，系统不能直接生成空泛方案。应先根据当前项目主题生成一批可用于规划的基础知识内容，并上传到当前项目知识库，再进入方案生成。

自动补充的知识内容应至少包含：

- 项目主题说明。
- 目标用户画像。
- 平台运营常识。
- 同题材内容方向。
- 竞品观察维度。
- 素材需求清单。
- 风险和禁用表达。
- 发布后需要回流的数据指标。

自动补充知识必须标记来源为“系统生成的项目启动知识”，后续允许人工替换、删除或补充真实资料。

## 4. 全网情报要求

方案阶段需要抓取和分析公开网络信息，但不能伪装成账号后台真实数据。

必须覆盖：

- 同题材热门视频线索：标题、封面方向、开场钩子、节奏、评论触发点和转化路径。
- 竞品打法：同类商家、本地生活、团购预约、短视频投放和私信承接方式。
- 平台公开资料：抖音、小红书、视频号等平台规则、商家运营说明和风控边界。
- 行业参考：本地到店、套餐转化、预约核销、会员复购等运营逻辑。
- 可视化参考：参考视频截图、封面结构、脚本结构、内容漏斗和发布节奏。

情报输出不能只展示搜索引擎字段、官网链接或 `bing_search`、`platform_reference` 等内部字段。必须转化为可执行洞察：为什么有用、对应方案如何调整、风险是什么、证据来源是什么。

## 5. LLM 方案对话

方案页应以大聊天框为主要工作区。用户通过与 LLM 对话生成、修改、比较和确认运营方案。

必须支持：

- 输入运营目标后生成候选方案。
- 用户继续修改方案，例如“更激进一点”“增加门店实拍”“减少数字人”“强化团购转化”。
- 每次修改生成新版本。
- 只把最新有效版本作为待审对象。
- 旧版本保留历史，但不重复派生生产任务。
- 用户能查看完整方案内容，而不是只看摘要卡片。
- 驳回方案后，该方案应从待审区消失或标记为无效，不再干扰当前流转。

## 6. 合格方案内容

一份可审批的运营方案至少包含：

- 项目目标拆解。
- 目标用户画像。
- 平台策略。
- 内容策略。
- 视频策略。
- 文案策略。
- 素材需求。
- 生产范围。
- 发布节奏。
- KPI 与验证指标。
- 风险与审核边界。
- 数据验证计划。
- 下一步派生任务。

方案不能出现未清洗的代码字段、内部字段、JSON 片段或模型原始结构。

## 7. 可视化要求

方案不应全是文字。页面应展示可用于审批判断的可视化内容：

- 热门视频线索卡片或截图预览。
- 封面与标题结构参考。
- 内容转化漏斗。
- 竞品打法对比表。
- 发布节奏表。
- 素材缺口清单。
- KPI 假设与验证表。

没有真实发布数据时，不得用假图表伪装成真实数据。方案阶段只展示情报分析和方案假设；真实指标必须进入数据回流板块。

## 8. 流转规则

方案批准后：

- 自动进入文案任务。
- 只从最新批准方案派生任务。
- 不重复显示多个同源文案任务。
- 文案批准后进入影音生成。
- 影音生成必须包含素材上传、工作流选择、候选产出预览和审批。
- 发布后才能进入数据回流和再次分析。

数据回流不能出现在第一步方案生产里。方案阶段可以定义数据验证计划，但不能展示尚未产生的真实回流指标。

## 9. 模型与资源调度

本地 70B 模型可负责方案规划和总结，但不能假装完成视频分析、图片生成或真实数据分析。

系统应支持或预留：

- 本地 LLM：方案对话和结构化方案生成。
- 视频分析模型：抽帧、ASR、OCR/VLM、镜头节奏和内容结构分析。
- 图片生成或编辑模型：封面、视觉参考和方案视觉化。
- 数据分析模块：发布后回流指标分析。
- GPU 调度：ComfyUI 运行时 LLM 使用空闲显卡；无 ComfyUI 任务时双 GPU 可用于 LLM 并发或分摊。
- 主 Agent / Codex 控制器：全局把控任务流、审批边界、模型路由、状态推进和验收。

## 10. 浏览器真实验证要求

所有方案相关功能交付前必须在浏览器中真实操作验证。

必须验证：

- 创建项目。
- 切换项目。
- 当前项目知识库检查。
- 知识库为空时自动生成主题知识并上传。
- 方案对话生成候选方案。
- 查看完整方案内容。
- 继续对话修改方案。
- 驳回方案。
- 批准最新方案。
- 自动流转到文案任务。
- 文案任务查看完整内容。
- 文案批准后流转到影音生成。
- 影音素材上传入口可用。
- 工作流候选选择可用。
- 候选产出预览和审批可用。
- 发布后数据回流入口和再次分析入口可用。

验证通过标准：

- 每一步都能通过页面点击完成。
- 页面状态刷新后仍正确。
- 不出现重复任务、无效按钮、字段泄露、假数据图表或跨项目数据混用。
- 后端接口有真实状态变化。
- Web 端和桌面端行为一致。

## 11. 不合格表现

以下情况视为不合格：

- 只生成简单口号式方案。
- 方案里没有具体执行细节。
- 情报来源为空或只有泛官网链接。
- 把公开资料伪装成真实后台数据。
- 方案内容无法完整查看。
- 方案无法通过对话修改。
- 驳回无效。
- 批准后重复派生任务。
- 文案或影音任务看不到完整内容。
- 影音生成缺少素材上传、工作流选择、产出预览或审批。
- 数据回流混在方案生成阶段。
- 只靠接口测试，没有浏览器真实点击验证。
